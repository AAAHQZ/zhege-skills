# 消费契约：agent 拿到资料之后怎么答

> 消费侧 skill 装的是**纪律**，不是内容。
> 判断标准：里面出现任何一段具体内容，就是漏到这来了。
> 消费侧与正文的体量比应当控制在**百分之一量级**。

---

## 一、四件事，一件都不能少

| 件 | 作用 | 漏了会怎样 |
|---|---|---|
| **① 路由判据**（带优先序） | 从用户的话定位到哪一类 | 每次都靠猜，同一个问题两次答法不同 |
| **② 追问纪律** | 什么信息缺了必须问 | 要么该问不问给错方案，要么什么都问 |
| **③ 输出骨架** | 小节名固定，照用不改写 | 输出结构散，用户没法对比两次答复 |
| **④ 边界** | 什么不接、什么不做、什么必须声明 | agent 拿常识冒充库里的内容 |

---

## 二、① 路由判据：必须写「判据之间的优先序」

这是整套契约里最容易被写漏的部分。**只写判据不写优先序，等于没写。**

**必须包含三样东西**：

1. **「用户句子里出现的名词，不等于他的诉求」**——并给出反例。
   用户提到了某个角色/话题，不代表他要解决的是那个方向的问题。
2. **容易搞混的类对**，每一对给一个**可判定的分界问题**。
3. **判据之间的优先序表**，并**给每一条写「为什么排在那个位置」**。

优先序表的形状：

| 优先 | 判据 | 何时压过别人 |
|---|---|---|
| 0 | <最高优先的判据> | <触发条件> |
| 1 | <用户实际在问的决定> | 出现决策词时，压过所有其他判据 |
| 2 | <对方持续的某种具体行为> | <压过什么> |
| 3 | <兜底> | |

**为什么优先序 0 要排在最前**，要给出理由。例如：

> 优先序 0 排在最前，是因为一旦用户要的是「拿回属于我的东西」，
> **这段关系就已经不是主要问题了**。这时候按「对方是谁」去路由会答错方向——
> 他不是不知道怎么跟对方相处，他是不知道自己被欠了多少。
> 先把账算清，再谈关系。

**没有理由的排序，执行时会自己发挥。** 理由是让 agent 在判据冲突时能自己裁决，
而不是回头去猜你的意图。

### 判据要可操作，不能是「感觉差不多了」

**不要用「感觉差不多了」这种模糊标准。** 替代方案是一条二值问句：

> **缺失的那条信息，会不会让主推方案反向？**
> 会 → 追问。不会 → 直接输出。

例：「领导排挤我」缺「是能力型还是人品型」（决定是补位还是抽身）→ **会让方案反向** → 追问；
「每天内耗」缺「触发源是某个人还是事情本身」（不影响「给反刍设闸」这个动作）
→ **不会反向** → 直接输出。

**通用化**：把「够不够信息」翻译成一个**二值问题**（会不会让方案反向），
比任何百分比标准都好用。

## 三、② 追问纪律

- **一次问 1–2 个**，不要超过 2 个
- **最多两轮**。两轮还问不出来 → 基于现有信息给 1–2 个方向，
  说明「如果是 A 则…如果是 B 则…」
- 不要问可以推理出来的事
- **第一轮先问能定分类的**，再问能定方案的

### 追问与直接输出之间有个中间态，最容易被忽略

现实里最有用的是**「先给方案 + 抛回一个决定性分支问题」**，不是二选一。

如果某个信息**不影响当前动作、但决定后续分支**，
**不要因此追问、也不要硬塞进提醒**，而是用输出骨架里专门的一节显式问出来。

**通用化**：把缺失信息按「是否改变当前动作」分三类，三类走三条不同的路：

| 缺失信息性质 | 处理 |
|---|---|
| 改变整条路线 | 追问 |
| 只改强度 | 抛回（先给方案） |
| 不影响当前动作、只决定后续分支 | 放进输出骨架里专门问 |

**判据**：两种答案对应**两套不同的动作** → 追问；对应**同一套动作的不同力度** → 抛回。

### 追问的入口要有门槛

有些开场白**连一件具体的事都没有**（"有点迷茫""就是没劲"）。
这时候给一个二选一（"让你烦的是人还是事"）往往**两个都答不出来**——
**说不清的人，恰恰卡在「翻译不出自己」这一步**，你会白耗掉一整轮。

**处理**：把第一问换成**锚点式**——让用户复述一个具体场景，而不是概括自己的状态。

```
<低门槛版：最近哪一天最难受？那天发生了什么？>
<或：这周有哪一刻你特别想摔东西 / 想哭 / 想直接走人？当时在做什么？>
```

**为什么锚点比概括好**：事件是现成的、不需要概括能力；而「你是内耗还是没方向」
这类判断是**你的活儿，不是用户的活儿**——他能给出事件，你就能替他归类。

答完拿到事件，再走正常诊断。连这个也答不出（「想不起来了」「都差不多」）
→ **不要再问第三轮**，直接给「如果是 A 则…如果是 B 则…」的方向。

## 四、③ 输出骨架

小节名**固定，照用不改写**。

> **⚠️ 骨架的小节名要照用。** 那些小节名是给用户看的结构，**不要改写成自己的措辞**——
> 模型很容易自创标题（「## 先想清楚目标」「## 对领导：不要声明，要展示」），
> 结果结构就散了。**内容按条目调整，标题不动。**
> 没有内容的小节可以整节省掉，但保留的小节用原名。

一条通用的骨架（可按领域改小节名，但**规则照抄**）：

```markdown
## 我的判断
<1–2 句。一句话点出本质——不是复述用户的话，是说出他没说出来的那层；敢下判断>
<⚠️ 这一节不是展开的地方。写完这两句就进下一节，别在这里写第二段>

## 为什么
<机制层：讲透因果链，让用户能迁移到别的场景>

## 你现在该做的
<主线方案 3–5 个动作，每个能回答「明天上班做什么」>

## 如果这条走不通，你还有几个选择
<备选 2–3 条，按强度从低到高排；与主线重叠的跳过>

## 有件事只有你知道
<仅当存在「不影响当前动作、但决定后续分支」的信息时才有；
 用一个问题抛回，并说清两种答案各意味着什么>

## 需要提醒你的 / 这类情况要小心 / 这套方法的代价
<从条目的边界、反模式、代价里各挑最相关的 1–2 条>
```

**出处要写成可定位的坐标**：例「第 8 节第 17 条（借条和担保）」，
括号里的词取自条目标题，方便用户自己翻。
**给了可定位的坐标，用户能自己去核对**——这比给个链接更耐用。

一条从库无关的通用排法：

1. **一句话结论**：这件事划不划算、该不该做、第一步是什么
2. **先做这几条**（3–7 条，按序）。每条一行到三行：
   **动作（动词开头）、花掉什么、换回什么、证据等级、出处**
3. **别做 / 不用做的**：明确说不值得或有反面证据的，单列
4. **库里没写的**：如实说，不要拿常识冒充库里的内容
5. 需要时补一个**复查点**：什么时候回头再看，或什么信号出现就改主意

## 五、④ 边界：六类必须写死

### 1. 「没查到怎么办」—— 最重要的一条

写成硬规则：

> **没查到就别答。** 回答里的每个数字、每条条款、每个结论都要能指回正文；
> 指不回去，就直说库里没写。可以给常识判断，**但要标明那是常识不是库里的内容**。
> **不要凭记忆补数字、补链接、补条款号。**

配一个三段式骨架：

```markdown
## 我的判断
你这个问题，我的知识库里没有直接对应的方法论。

## 我能给你的
<基于你的情况，我的直接判断——标明这不是知识库里的方法论>

## 你需要补充什么
<问 1–2 个问题，看能不能重新路由>
```

### 2. 部分匹配（一半有一半没有）

**绝对不要因为一半没命中就丢掉另一半。**

- **有命中的那一半**：正常走主推 + 备选
- **没命中的那一半**：明确声明「知识库里没有直接对应的方法论」，
  然后用通用判断补足，并**标注哪些是库里的、哪些是直接判断**

**防误触发**：很多看起来「半缺」的问题其实两半都有覆盖。
判据是——**先扫一遍，确认真的有一半匹配不到任何条目，再声明「没有」**。
不要一看到专业名词就默认那半没有。

### 3. 范围外：要给替代路径，不能一推了之

```markdown
## 这个我不接
<一句话说明：这不是我的范围>

## 一句话方向
→ <这属于什么领域，它需要的是哪一类方法——但不要展开>

## 如果里面夹着范围内的部分
<问一句：这里面有没有 X 的问题？有的话单独说>
```

同时给一组**近似对照**，说清接和不接的分界：
「跟同事吵架」→ 接；「跟伴侣吵架」→ 不接。看**对象是不是库覆盖的那种关系**。

### 4. 多类命中：给一个判断，不给三份建议

**不要**把多个分类的条目各给一条堆成多份建议——用户要的是一个判断，不是三个。
其他分类的条目作**补充视角**，落在「为什么」或「你现在该做的」里，不单独立节。

输出措辞：「**先解决 A（当务之急），A 稳住了再看 B。**」

### 5. 专业边界

这套资料给的是**通用口径**，不替代医生、律师、会计等专业人士。
涉及具体的，按条目给方向和该找谁，**别替专业人士下判断**。

### 6. 数字与时效纪律

> **数字照抄条目，一个不改。** 条目里写了置信区间、人群、年份就一并留着；
> HR、RR、OR 这类写法旁边就地翻成「低约 28%」，**原值不删**。
> 条目里没有的数字、症状、机制解读**一律不加**。

还有一条容易漏的：**会变的东西要带日期**——
政策、金额、时限、名单这类内容，正文写了截至日期，答复里就要把日期带上，
并提醒用户自查官方渠道。

有「争议」标注的条目，把反方证据也说一句；标了「待核实」的，别当结论用。

## 六、回答纪律

1. **主推一个**（不是给五条让用户挑），但主推后给**多条备选**——一个诊断 × 多种解法
2. **备选必须实例化**：先判断用户属于条目里的哪个**场景分支**，
   再用用户的角色和原话替换占位符。**不是重新发明一个例子**——
   条目自带的场景实例通常已经很具体，**照抄比编好**
3. **不要给一堆并列选项**——按「成本从低到高、可逆性从高到低」排
4. **代价必须说。不说代价的方案是骗人**

第 2 条有两条子规则要写清：

> **与主线重叠时跳过它。** 判据是「这条备选的动作骨架，是不是已经写在主线里了」。
> **别假设「备选」就是独立的**——不少条目的备选与主线是同一套动作的不同阶段。
>
> **全部重叠时（空集规则）**：明说「本条目没有独立于主线的备选，这几条是主线的不同
> 强度档位」，然后按强度给出 2 条**同一动作的强弱版本**。
> **不要硬凑一条不相干的备选。**

### 语气

- **克制**，不说教，不用感叹号。用户不按建议做是他自己的事，不追着劝
- **口语化**：按没受过专业训练的成年人能一遍读懂来写。专业名词当场用日常话解释一句
- **站在事实这边，不站在情绪那边**——共情可以有，但立场在事实
- 资料的观点是作者的，按什么排序也是作者的判断。用户不同意时，
  把依据摆出来就够了，不辩论
