# zhege-handoff（会话交接存档 + 决策条目化）

把一次聊完的会话压缩成两份产物：

1. **存档文档** —— 落在 `<workspace>/docs/session-archives/` 的 Markdown，给"以后回看 / 下一个会话接续"用。
2. **决策条目** —— 从会话里抽出值得长期保留的结论，**一条一个**问过用户后，写进项目指令文件（项目层）或长期记忆（用户 / agent 层）。

## 两条不可协商的规则

- **未经用户逐条确认，不写任何持久化文件**（`AGENTS.md` / `CLAUDE.md` / 记忆）。存档文档本身可以直接写。
- **只引用不复制。** 已经存在于 spec / plan / ADR / issue / commit / 代码 / 官方文档里的内容，存档里给路径或链接，不要抄一遍正文。

---

## 可移植性原则

**核心动作（读上下文、写 Markdown、列条目、逐条确认、写文件）任何 agent 都能做。** 只有三处天然依赖 runtime，每一处都有通用兜底：

| 环节 | 增强路径（runtime 支持时更好用） | 通用兜底（永远可用） |
|------|---------------------------|-------------------|
| 读会话 | runtime 的会话工具 / 落盘日志 | **直接复盘当前上下文**（最常用路径） |
| 逐条确认 | `ask_user` 之类问卷工具 | **纯文本列出候选表，问用户回复编号** |
| 长期记忆 | runtime 记忆工具（分层、可检索） | 写进纯文本指令文件（`AGENTS.md` / `CLAUDE.md` / `GEMINI.md`…） |

各 runtime 的具体调用方式、文件路径和**验证状态**见 `references/runtime-adapters.md`。**没验证过的路径不要写进存档**——按通用兜底走，并在存档里注明"本次基于当前可见上下文"。

## 步骤 0 · 能力探测（开工前 30 秒）

| 问 | 有 | 没有 → |
|----|----|--------|
| 能复盘当前对话上下文吗？ | 几乎总有 → 走 **T1**（步骤 1） | 停，直接告诉用户"本 runtime 无法读取会话历史" |
| 能读**别的**会话吗？ | 按 `runtime-adapters.md` A 节走 **T2/T3** | 只复盘当前会话，存档里注明范围 |
| 有问卷工具吗？ | 走 **工具确认**（步骤 4） | 走 **纯文本确认**（步骤 4） |
| 有跨会话记忆机制吗？ | 写进去（步骤 5） | 用户层条目写进该 runtime 的用户级指令文件；实在没有就**只留在存档里并明确告知用户无处可写** |

缺任何一项都**不阻塞流程**——降级执行，最后在报告里说清降级到哪一档。

---

## 步骤 1 · 采集会话历史（三级来源，从便宜到贵）

### T1 · 当前上下文（通用，默认走这条）

绝大多数情况——"把刚聊完的这次存档一下"——**对话本身就在上下文里**，不需要任何工具。

直接从上下文里提取：用户每一条 `msg_content`（需求、**纠正、拒绝、偏好**）与自己的最终结论、踩坑。这是零成本、零依赖、任何 runtime 都可用的路径。

局限：上下文被压缩或截断时，早期细节会丢。此时用 T2/T3 补，或在存档元信息里写明"基于压缩后的上下文"。

### T2 · runtime 会话工具（跨会话 / 补全完整历史）

有会话工具时用它读全量历史，**并分页**：

```jsonc
// mavis（MiniMax Code）——本机已实测
mavis({ command: "session get",      args: { session_id: "me" } })
mavis({ command: "session messages", args: { session_id: "me", limit: 20 } })
```

- `session_id: "me"` 表示当前会话；要复盘别的会话，换成 `session list` 拿到的 id（也可由用户在参数里直接给）。
- **翻页**：把返回的 `nextCursor` 填进下一次调用的 `before`，倒序翻到 `hasMore: false`（已实测有效）。
- 输出被 runtime 按 token 截断（只回传头尾预览）时，把 `limit` 降到 10 继续翻，**不要试图一次拉完**。

其他 runtime 的等价调用见 `references/runtime-adapters.md` A 节。

### T3 · 落盘日志（没有工具时兜底）

会话通常以 JSONL 落盘。Claude Code 位置已在本机确认：`~/.claude/projects/<cwd-slug>/<session-uuid>.jsonl`（全量）与 `~/.claude/history.jsonl`（**只有用户输入**，按 `sessionId`/`project`/`timestamp` 索引，适合快速定位"这次会话用户问过什么"）。其他 runtime 路径见 adapters 文档，**标注未验证的不要盲信**。

读 JSONL 时同样要**只取需要的字段**——原生日志会把完整的文件内容、工具输出全量存下来。

### 无论哪条路径：字段裁剪

| 取 | 内容 | 用途 |
|----|------|------|
| ✅ | 用户消息正文 | 需求、**纠正、拒绝、偏好**——最重要的证据来源 |
| ✅ | 助手最终答复正文 | 结论、踩坑、修复 |
| ✅ | 工具名 + 参数 | 用了什么手段 |
| ✅ | 工具成败状态 | 只判成败（mavis 经验值 2 成功 / 3 失败） |
| ❌ | 工具完整返回 / 读到的整份文件 | 动辄几万字符，是撑爆上下文的头号原因 |
| ❌ | `usage` / `context_usage*` / token 遥测 | 纯噪声 |
| ❌ | 思考过程 `thinking_content` | 除非要判断"为什么中途改了主意" |

会话超过 80 条消息时，先数规模，默认只复盘最近 30 条，并在存档元信息里注明。

## 步骤 2 · 写存档文档

**路径**：`<workspace>/docs/session-archives/session-<会话短 id>-<YYYYMMDD-HHMM>.md`

会话 id 取 runtime 能给的最短标识（mavis 是 `session.sessionId` 后 8 位；没有 id 就用标题 slug）。目录不存在直接创建。

**内容模板**：见 `references/archive-template.md`，照抄章节结构。必含：元信息（会话 id、**runtime 与模型**、时间范围、消息条数、workspace、git 分支 + HEAD + 未提交文件数、**本次复盘的数据来源与降级档位**）、一句话结论、时间线、关键决策清单、未完成 / 待验证、踩坑与修复、**建议能力/技能**、引用指针、脱敏。

用 `write` 工具落盘（**不要**用 PowerShell `Set-Content -Encoding UTF8`，会写进 UTF-8 BOM）。

## 步骤 3 · 条目化提取

完整判定标准、正反例、改写规则见 `references/extraction-rubric.md`。核心是一句话：

> **三问法**：换用户结论会变吗？换项目还成立吗？只是本次会话的临时状态吗？

产出 3–8 条候选，每条固定格式：

```
[D3] 结论前置的一句话（动词开头，≤ 60 字）
     证据：<用户原话片段> 或 <用户纠正："…">
     建议落点：项目层 / 用户层 / agent 层 / 丢弃
     理由：<为什么值得长期保留，一句话>
```

提取前先**去重**：搜已有的项目指令文件（`AGENTS.md` / `CLAUDE.md` / `GEMINI.md`…），有记忆工具的再把已有条目**完整读出来**逐条比对。命中就标 `[已存在]`，建议跳过或合并。

> ⚠️ **别只依赖 `search`。** 部分 runtime 的 `memory(operation=search)` 会**静默返回空**——即使条目确实存在（本机实测 4 次不同关键词全返回 `[]`，而 `read` 能读出全部内容）。**静默的空结果 = 假"不存在"= 允许重复写入。** 安全做法：先 `read` 拿到全文自己比对；`search` 只用来快速缩小范围，它的空结果永远不能当"确认不存在"的证据。

## 步骤 4 · 逐条确认

**一条一个**，不要把多条塞进一次问卷——用户要的是逐条过。

### 方式 A · 问卷工具（runtime 支持时）

```jsonc
ask_user({
  mode: "questionnaire",
  title: "会话存档 · 决策条目 3/7",
  steps: [{
    header: "条目 D3",
    // question 必须自包含：用户不看你上文也看得懂在问什么
    question: "这条要写进长期记忆吗？（原文：用户纠正'引用资料不能只给路径，要给出处'）",
    options: [
      { label: "写入长期记忆（用户层）", description: "换项目换用户都适用" },
      { label: "写入项目指令文件",       description: "落点 <workspace>/AGENTS.md「引用规范」小节 —— 只在本仓库适用" },
      { label: "跳过这条，不写入" }
    ]
  }]
})
```

> ⚠️ `ask_user` 会**结束当前 turn**，用户回答在下一轮回来。收到回答后处理下一条，直到候选过完。

### 方式 B · 纯文本（通用兜底，任何 runtime 都能用）

没有问卷工具时，在正文里给出候选表 + 明确回复格式，等用户下一条消息：

```
| # | 结论 | 建议落点 | 证据 |
|---|------|---------|------|
| D1 | 交付物默认不公开发布 | 用户层 | 用户纠正："A: Keep it local" |
| D3 | 引用资料要给出来处 | 项目层 | 用户原话 |

请按编号回复，例如：`D1 写记忆 / D3 写AGENTS / D2 跳过`。
不需要的一律不回复 = 跳过。
```

### 两条路径共同的硬要求

- **选项/回复项必须自包含**：写清"写到哪、什么后果"，不要只写"是 / 否"。
- **写明具体落点路径**，用户不看上文也知道会改哪个文件。
- 候选超过 6 条时，先给总览表——用户可能直接说"剩下的全跳过"，要支持这种批量应答。
- 用户给出**改写后的文案**（问卷 Other 字段或纯文本回复里）→ **按用户给的文案落盘**，不要回退到自己拟的版本。
- 这一步结束前，**任何持久化文件都不能写**。

## 步骤 5 · 落盘 + 验证 + 汇报

写法与校验规则见 `references/persistence-playbook.md`。三层落点的通用映射：

| 语义层 | 跨工具事实标准 | 说明 |
|--------|--------------|------|
| **项目层**（只在本仓库成立） | 仓库根 `AGENTS.md` | 纯 Markdown 无 schema，25+ 工具原生读取（Codex / Cursor / Copilot / Gemini CLI / Aider / Zed / opencode / goose / Warp / Devin / Junie / Amp / Windsurf…），由 Linux Foundation 下的 Agentic AI Foundation 治理 |
| **用户层**（换项目仍成立） | runtime 记忆工具 → 没有就用该 runtime 的**用户级指令文件** | mavis: `memory(target=user)`；Claude Code: `~/.claude/CLAUDE.md`；Codex: `~/.codex/AGENTS.md`；Gemini CLI: `~/.gemini/GEMINI.md` |
| **agent 层**（与用户无关的经验） | runtime 记忆工具的 agent 分层 → 没有就**只留在存档里** | mavis: `memory(target=main)`；没有对应机制时不要硬造文件，报告里明说"本条无处可写" |

关键坑：**Claude Code 不原生读 `AGENTS.md`**。同时用 Claude Code 和别的工具时，在 `CLAUDE.md` 里写一行 `@AGENTS.md`（Claude Code 会展开 @import），或 `ln -s AGENTS.md CLAUDE.md`。Windows 无 symlink 权限时用 @import 更稳。

**写完必须回读验证**：`read` 目标指令文件 / `memory(operation=read)` 确认落盘内容与用户确认的**逐字**一致。用户选了"跳过"的目标文件里必须**没有**这条。

最后给收尾表 + 存档路径：

| 条目 | 结论 | 落点 | 状态 |
|------|------|------|------|
| D1 | … | AGENTS.md「…」 | ✅ 已写入，回读确认 |
| D4 | … | — | ⏭ 用户跳过 |
| D6 | … | 长期记忆 (main) | ❌ 该条已存在，未重复写入 |

并说明降级情况（哪些环节走了兜底）、以及存档是否需要 commit（**不自动提交**，由用户决定）。

## 常见坑

| 坑 | 后果 | 正确做法 |
|----|------|---------|
| 只在 mavis 下能跑 | 换 agent 就废 | 核心流程不依赖工具；能力缺失走兜底 |
| 全量读会话返回 / JSONL | 上下文被工具结果撑爆 | 只取「字段裁剪」表里的 ✅ 项 |
| 一次性 `limit: 100` | 按 token 截断，只剩头尾 | `limit: 20` 起步，被截断就降到 10 |
| 忘记 `before` 翻页 | 只复盘最近几轮 | 翻到 `hasMore: false` |
| 把整份文件内容写进存档 | 存档体积爆炸 + 可能带出密钥 | 只引用路径、commit、行号 |
| 假设 `AGENTS.md` 到处都生效 | Claude Code 静默不读 | 加 `CLAUDE.md` 的 `@AGENTS.md` |
| 用户还没确认就写文件 | 污染持久化记忆且难撤销 | 步骤 4 结束前不写 |
| 写长期记忆用 `append` 改旧条目 | 产生重复条目 | 记忆工具用 `edit`；纯文本文件用 `edit` 工具 |
| PowerShell 写中文 Markdown | UTF-8 BOM，文件头多 `ï»¿` | 用 `write` 工具 |
| 报告"已写入"但没回读 | 假成功 | 回读是"已写入"的唯一凭据 |
